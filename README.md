# Конструктор SCORM-курсов

Веб-инструмент для сотрудников: загрузили документ (DOCX, PPTX, PDF) → модель предложила структуру курса →
вы поправили структуру → модель написала уроки и задания → вы отредактировали → скачали готовый SCORM 1.2 (.zip)
и загрузили его в портал (Websoft HCM, PHP-портал или любую LMS со SCORM).

## Возможности

- Структура курса из документа любого размера (до ~330 страниц): документ режется на фрагменты, каждый урок пишется по своим фрагментам.
- Уроки с визуальным редактором, 4 типа заданий (сопоставление, один правильный ответ, верно/неверно, порядок шагов), расчётное время прохождения.
- Картинки из DOCX и свои картинки в уроках, своё видео (файл или код для вставки с портала).
- Аудиоподкаст к уроку (полный пересказ голосом диктора).
- Обложки глав, готовый плеер внутри SCORM (работает без сети).
- Вход только через корпоративный OpenID, у каждого курса владелец, доступ коллегам (просмотр или редактирование), администраторы.
- Модель и озвучка подключаются переменными окружения: YandexGPT, корпоративный шлюз LLM (LiteLLM), любой OpenAI-совместимый сервер.

## Состав проекта

```
app/
  main.py            — API (FastAPI), вход и проверка прав на запросах
  auth.py            — вход через OpenID Connect, роли и права на курсы
  config.py          — все настройки (переменные окружения)
  models.py          — модели курса, главы, урока, заданий, подкаста
  file_parser.py     — текст и картинки из DOCX/PPTX/PDF
  chunking.py        — фрагменты документа, дайджест для структуры, подбор фрагментов для урока
  images.py          — картинки: сжатие, подписи, расстановка в уроках
  generator.py       — промпты и генерация структуры, уроков, заданий, обложек
  llm.py             — клиент модели (YandexGPT или OpenAI-совместимый), очередь, повторы, счётчик токенов
  jobs.py            — фоновые задачи (генерация уроков, подкасты) с прогрессом
  podcast.py         — сценарий подкаста из текста урока
  tts.py             — озвучка (Yandex SpeechKit или OpenAI-совместимый сервер)
  pronunciation.py   — как читать аббревиатуры при озвучке
  media.py           — загрузка и выдача видео, картинок, аудио (по частям, с Range)
  storage.py         — хранилище курсов в файлах JSON
  scorm_builder.py   — сборка SCORM 1.2 (.zip)
  cover_icons.py, cover_builder.py — процедурные обложки глав
  scorm_assets/      — плеер (player.js/css, scorm_api.js, lesson_content.css), попадает в КАЖДЫЙ курс
  templates/         — шаблоны player.html и imsmanifest.xml
  static/            — интерфейс (index.html, app.js, styles.css); editor.bundle.js — собранный редактор
editor-src/          — исходники визуального редактора (TipTap), нужны только для пересборки бандла
data/                — загрузки, курсы, сборки, медиа (создаётся автоматически)
```

## Быстрый старт (локально)

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
export YANDEX_API_KEY=...        # ключи только в переменных окружения, в код не вписываются
export YANDEX_FOLDER_ID=...
./venv/bin/uvicorn app.main:app --reload
```

Открыть http://localhost:8000. Пока не задан `OIDC_ISSUER`, вход отключён (`AUTH_MODE=off`, доступ открыт всем): это режим разработки, на рабочем сервере так оставлять нельзя.

| `OIDC_TOKEN_AUTH` | `post` | как передавать секрет клиента: `post` или `basic` |
| `OIDC_CA_BUNDLE` | как `LLM_CA_BUNDLE` | сертификаты провайдера входа |
| `OIDC_END_SESSION` | `0` | `1`: при выходе завершать сессию и у провайдера |

**Файлы и размеры**

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `MAX_VIDEO_MB` | `150` | размер одного видео |

## Языковая модель

Модель выбирается переменными, код менять не нужно. Промпты писались под YandexGPT: при смене модели прогоните несколько реальных курсов и при необходимости подстройте их (`app/generator.py`).

**YandexGPT:** `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`.

**Корпоративный шлюз LLM (LiteLLM, формат OpenAI):**

```
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://api.ai-test.localcorp.net/v1     # тестовый контур; у продуктива свой адрес и свой ключ
LLM_API_KEY=<ключ, полученный через IDM>
LLM_MODEL=<имя внутренней модели из /v1/models>
LLM_JSON_MODE=1
```

- Используйте только внутренние модели: шлюз также маршрутизирует запросы к внешним провайдерам, а в запросах уходят тексты ваших документов.
- У моделей шлюза лимит потоков для автоматики (1 для gpt-oss-120b, 3 для Qwen): настройте `LLM_MAX_CONCURRENCY` под модель. Остальные запросы (другие курсы, подкасты) ждут в очереди.
- Если сервер не принимает необязательные параметры (`chat_template_kwargs`, `response_format`), приложение один раз повторяет запрос без них и дальше их не отправляет.
- `GET /api/llm/usage` показывает число запросов и токенов (вход и выход) с момента запуска: удобно, чтобы замерить реальную нагрузку.
- Amvera находится вне корпоративного контура и до внутреннего шлюза не достанет: проверку на корпоративной модели делайте на сервере внутри контура.

## Вход через корпоративный OpenID и доступ к курсам

Своих логинов и паролей в приложении нет: вход только через корпоративный OpenID Connect (код авторизации с PKCE). Если сотрудник уже вошёл на портал, переход в конструктор проходит без запроса пароля.

В OpenID нужно зарегистрировать клиента с адресом возврата из `OIDC_REDIRECT_URI`. В токене должен приходить адрес почты: по нему определяются владелец курса и доступ коллег. За обратным прокси (HTTPS завершается на нём) приложение запускается с `--proxy-headers` (в Dockerfile уже есть); при необходимости задайте `FORWARDED_ALLOW_IPS`.

Кто что может:
- **Владелец** (создавший курс): всё, включая удаление курса и настройку доступа («Поделиться» в шапке).
- **Редактирование** (коллега): править структуру и уроки, генерировать, собирать SCORM. Удалять курс и менять доступ нельзя.
- **Просмотр** (коллега): читать курс и скачивать уже собранный SCORM. Кнопки изменения скрыты, сервер такие запросы отклоняет.
- **Администратор** (из `ADMIN_EMAILS`): видит и правит все курсы, меняет доступ, удаляет.
- Коллеге курс виден в «Мои курсы» после того, как владелец добавил его адрес почты. Курсы, к которым нет доступа, для пользователя не существуют (ответ «не найден»).
- Файлы в `/media/...` (картинки, видео, аудио) доступны любому вошедшему сотруднику по длинному случайному адресу: доступ к отдельным файлам не проверяется.

## Развёртывание

**Amvera (тестовый контур).** Файл `amvera.yaml` должен лежать в корне репозитория рядом с `Dockerfile`: без него Amvera считает порт приложения равным 80, а мы слушаем 8000, и отдаёт 503. В файле уже заданы порт 8000 и постоянное хранилище `/srv/data`: курсы, загрузки и медиа переживают перезапуск и обновление.
1. Создать проект на amvera.ru, тип Docker.
2. В настройках добавить переменные окружения: `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`. Если вход не настроен, приложение работает с открытым доступом (`AUTH_MODE=off`): для теста нормально, для рабочего сервера нет.
3. Залить репозиторий (git push в Amvera-remote); платформа соберёт образ и запустит контейнер.

**Корпоративный контур.** Запускайте в Docker на сервере, из которого доступны шлюз LLM (`api.ai.localcorp.net`) и сервер озвучки; задайте переменные входа и модели из таблиц выше. Node в образе не нужен: редактор уже собран.

**Подключение к порталам.** Порталы (Websoft HCM, PHP) принимают SCORM 1.2: сотрудник собирает курс в конструкторе, скачивает `.zip` и загружает его в портал. Конструктор открывается на портале ссылкой в новой вкладке. Размер пакета ограничен лимитом портала (`SCORM_MAX_MB`).

## Как это работает

### Загрузка и большие документы

Файл (DOCX, PPTX, PDF до 30 МБ) загружается по частям по 512 КБ (`/api/upload/chunk`, `/api/upload/complete`), поэтому лимит размера запроса на прокси не мешает. Скан без текстового слоя не читается, будет сообщение об этом.

Текст режется на пронумерованные фрагменты по заголовкам (стили DOCX, заголовки слайдов, «1.2 Название», «Глава N»). При создании структуры модель получает дайджест всего документа (до `STRUCTURE_SOURCE_CHARS`) и указывает для каждого урока номера фрагментов. При написании урока в запрос идут только его фрагменты (до `LESSON_SOURCE_CHARS`); если привязки нет (урок добавлен вручную), фрагменты подбираются по словам из названия. При охвате «Полностью» фрагменты, которые модель не отдала ни одному уроку, присоединяются к ближайшему предыдущему уроку. Небольшие документы передаются целиком.

### Интерфейс

- **Старт:** слева файл, тема, аудитория, охват курса, подробность уроков, язык; по центру структура после генерации (переименование, перетаскивание, удаление); справа превью. Тему и аудиторию можно не заполнять: если есть файл, их определяет модель.
- **Охват курса** («Основное» / «Стандарт» / «Полностью») определяет число глав и уроков; в режиме «Полностью» структура следует разделам документа.
- **Подробность уроков:** «Кратко» (150–250 слов, 1 задание), «Стандарт» (300–500 слов, 1 задание, по умолчанию), «Подробно» (500–800 слов, 2 задания).
- **Время прохождения** не вводится, а рассчитывается: слов / 180 в минуту плюс около 40 секунд на задание.
- **Работа:** слева структура, по центру редактор урока, подкаст и задания, справа превью «как увидит ученик» (настоящий плеер SCORM). Задания редактируются прямо в карточке. Изменения сохраняются автоматически через 1,5 секунды.
- **Мои курсы:** свои курсы и курсы, открытые вам коллегами (открыть, удалить свои). **Поделиться:** доступ коллегам по email. Шрифты подгружаются с Google Fonts, без интернета используется системный.

### Фоновая генерация

«Сгенерировать все уроки» и «Подкасты для всех уроков» работают в фоне (`app/jobs.py`): интерфейс опрашивает статус и показывает «Готово 5 из 12». Готовое появляется по мере написания, задачу можно остановить, а после перезагрузки страницы наблюдение продолжается. Уроки с текстом автора не перезаписываются, правки во время генерации не теряются. Пока идёт генерация, структуру курса менять нельзя.

Задачи живут в памяти процесса: приложение должно работать в одном экземпляре, при перезапуске задача прерывается (готовое остаётся, недостающее допишется повторным запуском). О переходе на настоящую очередь см. раздел в конце.

### Визуальный редактор

TipTap: заголовки, жирный, курсив, подчёркивание, ссылки, списки (нумерованные отображаются как шаги), цитата, выравнивание, разделитель, врезки («Важный факт», «Совет», «Предупреждение»), меню блоков по «/», картинки и видео. Стили текста лежат в `app/scorm_assets/lesson_content.css` и используются и в редакторе, и в плеере. Редактор вырезает любые теги и атрибуты вне своей схемы (в том числе `script` и `onclick`).

Бандл `app/static/editor.bundle.js` уже собран и лежит в репозитории. Если меняете `editor-src/editor.js`: `cd editor-src && npm install && npm run build`.

### Картинки

**Из документа (DOCX и PPTX).** Переносятся скриншоты и схемы; значки, линии и повторяющиеся логотипы отбрасываются. Картинки сжимаются (длинная сторона до 1600 px) и хранятся в `data/media/`. В DOCX учитываются картинки внутри групп фигур и подписи в текстовом поле. В запрос для модели картинка попадает как `[[Рисунок N]] подпись`; модель ставит пометку в нужное место урока, и она заменяется на картинку с подписью. Если пометки нет, картинка добавляется в конец урока, только когда подпись или текст рядом совпадают с названием урока. Модель может поставить в урок до 10 картинок, сами мы добавляем в конец не больше 3. Повторов между уроками нет. Картинки из PDF пока не переносятся; курсы, созданные до этой функции, картинок не содержат.

**Из презентации (PPTX).** Картинка попадает в текст после текста своего слайда. Что отбрасывается: фото и оформление титульного слайда, значки и мелкие картинки (меньше примерно 6% слайда по ширине или высоте), картинки на весь слайд под текстом (фон), одна и та же картинка на трёх и более слайдах (логотип, водяной знак), векторные EMF/WMF. Обрезанные в PowerPoint картинки берутся уже обрезанными. Подпись: короткий текст прямо под картинкой на слайде; если его нет, описание картинки (alt-текст), если и его нет, а на слайде одна картинка, то заголовок слайда. Старый формат PPT не поддерживается: сохраните презентацию как PPTX.

**Свои.** Кнопка «Картинка», пункт «Картинка» в меню по «/», вставка скриншота (Ctrl+V) или перетаскивание файла: PNG, JPEG, WebP, GIF до `MAX_IMAGE_MB`. В плеере картинка открывается на весь экран по клику. «Убрать картинку» есть в редакторе.

### Видео

Кнопка «Видео» (и пункт в меню по «/»), две вкладки:
- **Своё видео:** MP4 (H.264) или WebM до `MAX_VIDEO_MB`. Грузится по частям по 1 МБ, копируется в SCORM-пакет (`media/`) и играет без интернета. Формат проверяется по содержимому файла (MOV, AVI, MKV не принимаются).
- **Код для вставки:** код `<iframe …>` из видеоплеера портала (HLS) или ссылка на YouTube, RuTube, Vimeo, VK Видео. В пакет не копируется: играет, только если у ученика есть доступ к этому адресу.

Если видео не воспроизводится на iPhone, перекодируйте его в MP4 с кодеком H.264 (не HEVC).

Видео и картинки, добавленные вручную, при «Перегенерировать урок» сохраняются: переносятся в конец нового текста. Файлы из удалённых уроков и курсов остаются в `data/media/`, пока администратор не запустит очистку (см. ниже).

### Подкасты

К каждому уроку можно создать аудиоверсию: полный пересказ урока одним диктором. В редакторе под текстом урока блок «Подкаст», слева кнопка «Подкасты для всех уроков». В плеере над текстом урока появляется блок «Послушать урок» со скоростью 1×, 1,25×, 1,5×.

Модель переписывает урок как речь (без списков и таблиц, числа и аббревиатуры словами), затем текст озвучивается. Текст подкаста можно править и нажать «Озвучить заново». Если после создания подкаста текст урока изменился, редактор предупредит, что аудио устарело. Подкасты в SCORM копируются в `media/`; минута аудио весит около 0,4 МБ. Аудио удалённых подкастов остаётся в `data/media/` до очистки.

Произношение: аббревиатуры заменяются перед озвучкой («PLM» → «пи эл эм»). Свои слова добавьте в `data/pronunciation.json`, перезапуск не нужен:

```json
{"ЕСКД": "е эс ка дэ", "Teamcenter": "тим сентер"}
```

Для внутреннего контура нужна локальная модель озвучки. Перед выбором проверьте лицензию: например, Silero распространяется на условиях CC BY-NC (коммерческое использование нужно согласовывать); качество русского и ударений нужно послушать на ваших текстах.

### Обложки глав

Кнопка «Обложки глав» подбирает для каждой главы локально, без внешних запросов: набор иконок по ключевым словам названий (`cover_icons.KEYWORD_MAP`, около 25 иконок) и палитру (одна и та же глава всегда получает одну палитру, 8 вариантов). Из этого собирается SVG и сохраняется в данных курса. Чтобы расширить тематику: добавьте иконку в `ICONS` и строки в `KEYWORD_MAP` (`app/cover_icons.py`), новую палитру в `PALETTES` (`app/cover_builder.py`).

### Очистка неиспользуемых файлов

Видео, картинки и аудио из удалённых или переделанных уроков остаются в `data/media/`. Очистка удаляет только то, на что не ссылается ни один курс:
- видео, картинки и аудио, которых нет ни в одном уроке (картинки документов, привязанных к курсам, сохраняются);
- загруженные документы без курса старше `CLEANUP_UPLOAD_DAYS` дней вместе с их текстом и картинками;
- обрывки незавершённых загрузок и сборки (папка и zip) курсов, которых больше нет.

Файлы моложе `CLEANUP_MIN_AGE_HOURS` не удаляются: их могли только что загрузить и ещё не вставить в урок. Если файл какого-то курса не читается, очистка останавливается и ничего не удаляет.

Запуск: администратор открывает «Мои курсы» → «Очистка файлов»: приложение показывает, что будет удалено и сколько места освободится, и удаляет только после подтверждения. Из командной строки: `python -m app.cleanup` показывает, `python -m app.cleanup --apply` удаляет. Перед первой очисткой на рабочих данных сделайте копию `data/`.

### Сборка SCORM

«Собрать SCORM» создаёт пакет SCORM 1.2 с одним SCO на весь курс: плеер, уроки, задания, картинки, видео и аудио внутри, без обращения к сети (кроме видео по коду для вставки). Прохождение и оценка сохраняются в LMS. Чтобы добавить новый тип задания: модель в `models.py`, схема в `generator.QUIZ_TYPE_SHAPES`, рендерер в `player.js` (`QUIZ_RENDERERS`) и стили в `player.css`.

## Когда понадобятся база данных и очередь задач

Сейчас курсы хранятся файлами JSON в `data/`, а фоновые задачи работают в потоках приложения. Для 1–2 сотрудников одновременно и одного экземпляра этого достаточно: регулярно копируйте папку `data/`, не перезапускайте приложение во время генерации (если задача прервалась, «Сгенерировать все уроки» допишет недостающее, готовые уроки пропускаются) и периодически запускайте очистку файлов.

Переходить на базу данных (PostgreSQL) и настоящую очередь задач стоит, когда появятся несколько экземпляров приложения, десятки сотрудников одновременно, сотни курсов с поиском или требование корпоративного бэкапа и аудита. Доступ к курсам идёт через `app/storage.py`, поэтому замена хранилища затронет в основном его. Задачи (`app/jobs.py`) тогда удобнее хранить в таблице базы и выполнять отдельным воркером.
