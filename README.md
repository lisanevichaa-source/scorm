# Конструктор SCORM-курсов

MVP-инструмент для сотрудников: загрузка исходных материалов → генерация структуры курса через
YandexGPT → редактирование структуры → генерация контента уроков (с квизом-сопоставлением) →
сборка готового SCORM 1.2 пакета (.zip).

## Состав

```
app/
  main.py          — FastAPI-эндпоинты
  config.py        — настройки (ключи из переменных окружения)
  models.py        — модели курса/главы/урока
  file_parser.py   — извлечение текста из DOCX/PPTX/PDF
  yandex_gpt.py     — клиент YandexGPT
  generator.py      — промпты и генерация структуры/контента; подбор обложки главы
  cover_icons.py      — библиотека флэт-иконок + подбор по ключевым словам темы
  cover_builder.py     — сборка SVG-обложки (градиент + иконки), палитры
  storage.py        — файловое хранилище курсов (MVP; заменить на БД для прод)
  scorm_builder.py  — сборка SCORM 1.2 zip
  scorm_assets/      — JS/CSS плеера, которые упаковываются В КАЖДЫЙ курс
  templates/         — Jinja2-шаблоны player.html и imsmanifest.xml
  static/            — фронтенд конструктора (3 экрана)
data/                — файлы загрузок/курсов/сборок (создаётся автоматически)
```

## Локальный запуск

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
export YANDEX_API_KEY=...
export YANDEX_FOLDER_ID=...
./venv/bin/uvicorn app.main:app --reload
```

Открыть http://localhost:8000

## Деплой на Amvera (тестовый контур)

1. Создать новый проект на amvera.ru, тип — Docker (Dockerfile уже в репозитории).
2. В настройках проекта добавить переменные окружения: `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`,
   (опционально `YANDEX_MODEL`, по умолчанию `yandexgpt`).
3. Залить репозиторий (git push в Amvera-remote согласно их инструкции) — платформа соберёт
   образ по Dockerfile и запустит контейнер на порту 8000.
4. Важно: каталог `data/` сейчас хранится на локальном диске контейнера — при пересоздании
   контейнера данные (черновики курсов) потеряются. Для теста это нормально. Для прод-версии
   на корпоративном портале — см. раздел «Что доработать перед продакшеном».

## Обложки глав (процедурная генерация, без внешних API)

На экране редактора уроков есть кнопка «Сгенерировать обложки глав»: для каждой главы локально,
без единого сетевого запроса, подбирается:
- **набор иконок** — по ключевым словам из названия главы и её уроков (`cover_icons.KEYWORD_MAP`,
  ~25 иконок: документы, склад, финансы, люди, графики, безопасность и т.д.; если ключевых слов
  не нашлось — подставляются нейтральные иконки по умолчанию);
- **цветовая палитра** — детерминированно по названию главы (одна и та же глава всегда получит
  одну и ту же палитру), из 8 заготовленных вариантов.

Из этого собирается SVG (градиентный фон + коллаж иконок в бейджах), кодируется в
`data:image/svg+xml;base64,...` и сохраняется прямо в данных курса — так же, как встраивается в
player.html внутри SCORM-пакета. Работает мгновенно, бесплатно, полностью оффлайн внутри LMS.

Чтобы расширить тематику (например, под конкретную отрасль): добавьте новую иконку в
`ICONS` и строки в `KEYWORD_MAP` (`app/cover_icons.py`), при желании — новую палитру в
`PALETTES` (`app/cover_builder.py`).

Обложки генерируются только на уровне главы (не урока) — так решили для MVP.

## Что доработать перед продакшеном (корпоративный портал)

- **Хранилище** — перенести курсы/загрузки из локальных JSON-файлов в БД (Postgres) и
  object storage (S3-совместимое) вместо `data/`.
- **Авторизация** — сейчас эндпоинты открыты всем; нужна интеграция с SSO/корп. авторизацией
  и привязка курсов к пользователю (сейчас любой, кто знает course_id, может его редактировать).
- **Очереди для долгих LLM-запросов** — генерация всех уроков сразу (`/generate-all`) сейчас
  синхронная и может быть долгой; для десятков уроков стоит вынести в фоновую задачу
  (Celery/RQ) с прогресс-баром на фронте.
- **Квизы** — реализовано 4 механики (сопоставление, один правильный ответ, верно/неверно,
  последовательность — drag&drop), LLM чередует их по курсу (`QUIZ_TYPES` в `models.py`).
  Чтобы добавить ещё один тип: модель в `models.py`, схема в `generator.QUIZ_TYPE_SHAPES`,
  рендерер в `player.js` (`QUIZ_RENDERERS`) + стили в `player.css`.
- **SCORM 2004 / множественные SCO** — сейчас один SCO на весь курс (SCORM 1.2). При
  необходимости постраничного трекинга в LMS можно сделать по SCO на главу.
- **Видео в уроках** — поле для видео в модель Lesson не добавлено, на макете (рис. 3) есть
  видеоплеер — надо решить, откуда брать видео (загрузка файла / ссылка / генерация).
- **Лимиты/ретраи** YandexGPT — добавить обработку rate-limit (429) с повтором и таймауты.

## Проверка пайплайна без реального вызова YandexGPT

В коде нет тестового режима "в комплекте", но пайплайн генерации уже проверен end-to-end с
подменённым ответом модели (структура → контент → сборка SCORM) — он рабочий. Как только
проставите `YANDEX_API_KEY`/`YANDEX_FOLDER_ID`, реальные вызовы пойдут по тому же пути.
